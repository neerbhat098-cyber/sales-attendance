Sales Attendance System — Start Day / End Day Issue
1. Current Situation

The attendance system is connected to Supabase.

There are two types of users:

EMPLOYEE / Sales Person

ADMIN / System Admin

The important behavior currently is:

Sales person → Start Day works.

Sales person → End Day works.

System Admin → Start Day works.

System Admin → End Day does NOT properly record/update the ending details.

Therefore, the problem appears to be specific to the System Admin attendance record, ID matching, or admin-specific database data rather than the general End Day functionality.

4. Important Attendance Matching Logic

Today's attendance is found with:

function getTodayAttendance() {

    if (!currentUser) {
        return null;
    }

    return attendance.find(
        item =>
            (item.employeeId || item.employee_id) === currentUser.id &&
            (item.workDate || item.work_date) === todayString()
    );
}


This means the System Admin must have an attendance record where:

employee_id = ADM001


and:

work_date = today's date


If the System Admin attendance record uses a different employee ID, getTodayAttendance() will return null.

6. End Day Flow

When End Day is pressed:

function endDay() {

    const record = getTodayAttendance();

    if (!record) {

        showToast(
            "Today's attendance has not started."
        );

        return;
    }

    if (record.status !== "ACTIVE") {

        showToast(
            "Attendance is already closed."
        );

        return;
    }

    // ...
}


The application then gets the final location and creates:

record.endTime =
    now.toISOString();

record.status =
    "COMPLETED";

record.endType =
    "MANUAL";

record.totalWorkMinutes =
    calculateMinutes(
        record.startTime,
        record.endTime

Then it updates Supabase:

const attendanceUpdate = {

    end_time:
        record.endTime,

    end_latitude:
        record.endLatitude || null,

        record.endLongitude || null,

    end_accuracy:
        record.endAccuracy || null,

    end_address:
        record.endAddress || null,

    status:
        record.status,

    end_type:
        record.endType,

The database update is:

const { data, error } =

Since the normal salesperson's End Day works, this update mechanism is probably generally valid.

7. Most Likely Problem

Because:

Salesperson Start Day       → works
Salesperson End Day         → works
System Admin Start Day      → works
System Admin End Day        → fails


the first thing to investigate is the System Admin attendance record.

The most likely possibilities are:

currentUser.id for System Admin is not actually ADM001.

The System Admin attendance row has a different employee_id.

getTodayAttendance() cannot find the System Admin's row.

The System Admin record has an unexpected status.

The Supabase attendance row ID does not match the frontend record.id.

A Supabase RLS policy is treating the admin record differently.

The database update succeeds but the UI/table is rendering stale data.

10. What the Console Results Mean
Case A — END DAY RECORD: null

This means:

getTodayAttendance()


cannot find the System Admin's attendance.

The problem is probably an ID or date mismatch.

We need to compare:

currentUser.id


with:

attendance.employee_id


and:

current date


with:

attendance.work_date

Case B — The record appears but Supabase reports an error

Then the problem is probably:

RLS

database permissions

invalid column

UUID mismatch

database constraint

The exact Supabase console error will tell us which one.

Case C — The record appears and Supabase update succeeds

Then the End Day database operation is working.

In that case the remaining problem is the frontend table/rendering.

13. Important Separate Issue — Auto Close

There is also another issue in the current code.

autoCloseAttendance() modifies the local JavaScript object:

record.endTime =
    end.toISOString();

record.status =
    "AUTO_CLOSED";

record.endType =
    "AUTO_MIDNIGHT";

record.totalWorkMinutes =
    calculateMinutes(
        record.startTime,
        record.endTime
    );


But it does NOT update the Supabase attendance table.

It only later calls:

saveStorage(
    "sales_attendance",
    attendance
);


Therefore:

Manual End Day
→ Supabase update exists

Auto Midnight Close
→ Supabase update is currently missing


This should be fixed after the System Admin manual End Day issue is solved.
